# PB-053 isolated Linux/BlueZ host lane

## Purpose and boundary

A pinned booted-system profile anchors this lane: the pinned booted-system Linux 7.1.5 kernel image, matching config and modules are used, **not** the current generation's kernel, which at readiness review time was a different kernel generation and must never be mixed with the pinned modules.

This is a separately selected, local Linux/BlueZ host-stack regression lane. It tests real encoded public D-Bus and ISO transport behavior inside a private QEMU guest. It does not establish physical nRF RF delivery, firmware behavior, independent LC3 codec/conformance, PCM, I2S, analog sound, presentation timing, or release acceptance. The fixture LC3 bytes are **valid transport stimulus only**. No vendor LC3 terms, reference tool execution, or redistribution right is implied. PB-051 input-validation work remains outside this lane; firmware ASCS validation is a separate contract in `docs/testing/ascs-protocol-regression.md`.

The current machine-specific profile is pinned in `scripts/bluez_host_guest.py`: booted Linux 7.1.5 kernel image, matching modules and config; installed BlueZ 5.87 daemon; QEMU 11.0.2; Python 3.13.12, dbus-python 1.4.0 and GI/GLib runtime; and independently built `btvirt` from clean BlueZ source revision `4dc15be8ee3f7422d447087f1893d215575cb2c8`.

The emulator's pinned binary SHA-256 is `06611569862825010327200c354377428e996dade36d96c1a4872eb20ed0083c`. These pins are a historical record of one reviewed setup, enforced script-side on this machine only; they are not a default configuration other PCs can reuse, and no approval rights transfer with them. The dated readiness checks behind these pins verified the matching 7.1.5 module store root (`lib/modules/7.1.5` with indexes, VHCI, Bluetooth and crypto dependencies, vermagic `7.1.5 SMP preempt mod_unload`) and that `/proc/config.gz` is the matching config with proc/sysfs/devtmpfs/8250 console, initrd/gzip and ELF support built in and Bluetooth, VHCI and crypto as modules; the staged BusyBox shell is shell-only, so mount and modprobe are separately pinned executables.

GPL/LGPL component notices remain in the private local runtime; no packaged vendor assets or redistribution claim follows.

Source and build pins, exact absolute runtime paths, emulator mode and staged source hashes are verified, not discovered by searching installed versions.

Other machines must deliberately provision and review equivalent pinned capabilities; missing prerequisites fail, without automatic downloads, installers or host module/kernel changes.

Native source-snapshot unit tests use an authored temporary byte fixture, **not** the real emulator. The pure `freeze_sources` helper takes a keyword-only `expected_emulator_sha` and rejects a lowercase-64-hex mismatch against the computed emulator entry; the production caller keeps the unchanged default pin.

QEMU has one vCPU (`host,ssbd=off`), 4096 MiB memory, `-nodefaults`, `-no-user-config`, `-nic none`, no display or monitor and no host shares, passthrough or host adapter/device/bus export. The custom initramfs uses PID1 and guest-only kernel crypto/ISO modules, two guest-only emulated VHCI controllers, a private D-Bus, BlueZ daemon and `/var/lib/bluetooth` state. No workstation Bluetooth adapter, `/dev/vhci`, host root/home/run or privileged RPC is used. Host process groups, per-process subreaper/pidfd ownership and restoration constrain children and detached descendants. A previously exited actor, even with code 0, cannot masquerade as an owned stop. Host-run SIGINT/SIGTERM is first-signal latched across input snapshots, VM ownership, post-processing and record sealing.

## Acquire and cleanup ordering

The guest child starts the **source** `Acquire` first; the sink `Acquire` starts only after the sink transport publicly reports `State == pending`, observed with a bounded 10-second poll. The two Acquire requests are not started simultaneously; both leases may subsequently be held. The Acquire owner (`scripts/bluez_guest_acquire.py`) accepts at most two requests, each taken exactly once. Unknown, late or duplicate token replies close their newly transferred fd, record a failure and cannot overwrite an already owned fd.

On the failed-acquisition cleanup path the owner freezes before public `Release` attempts, unclaimed requests are released source before sink, retained `PendingCall` handles are canceled after the Release attempts, remaining unclaimed fds are closed independently, and each request's fd field is set to `None` before close so a reused numeric fd cannot be closed twice. A `Release` error on the failed path is recorded as a failure, never accepted as lease success.

On the success path the source lease is released while its fd is still owned, requiring a normal D-Bus Release reply; its local socket is closed afterward. Then the child awaits sink idle plus an observed `POLLHUP` and closes the sink socket, never calling a second sink `Release` after proved revocation. If only a sink lease exists on an earlier failure, the child attempts its ordinary explicit Release and close and still records a failed result.

The pinned BlueZ `src/shared/bap.c:2192-2202` server Release disables locally first; releasing the server first and then the client sends another Disable into QoS, producing Invalid ASE State. The current public child therefore releases source first, unlike an earlier fixture that released sink first. Pinned `profiles/audio/transport.c:1801-1823` and `2324-2354` revoke the server-side owner when peer state enters QoS, so a second server Release is not guaranteed legal: revocation is proved through `State` and the fd, never an accepted `NotAuthorized`.

Device1 cleanup disconnects sequentially, source side first, requiring both peers observed `Connected=false` within the overall 10-second deadline; a snapshot pair must stay false for 0.5 s inside that original budget. The reciprocal second Disconnect, sent while already disconnected, disables the remaining policy without a duplicate ACL command; the advertisement stays registered until the state proof, then advertisement/endpoints/agent unregister. Pinned BlueZ `src/device.c:2372-2386` disables each untrusted peer's autoconnect first and `src/device.c:2117-2120` replies immediately if already disconnected; earlier simultaneous Disconnects caused duplicate MGMT disconnection warnings. Citations bind BlueZ `4dc15be8ee3f7422d447087f1893d215575cb2c8`, not a newer source.

## Public state and ISO delivery

Initial Device1 identity comes from the opposite known controller address, not the device's self-reported `Address`; callback-derived transport paths must descend from their respective paired peers. `SetConfiguration` callbacks may arrive during `Pair`/`Connect`, so a strict callbacks-after-`Pair` ordering is not required and would be wrong. Disconnect-cleanup `ok` must be exact boolean `true`, not numeric `1`.

The ISO delivery phase sends the first 16 distinct pinned 120-byte fixture frames from the source socket, one frame per ISO message, with 3-second socket deadlines (the send must return exactly 120) and 10 ms spacing measured from a monotonic deadline. The sink uses the libc `receive_packet` helper with a 121-byte receive capacity; each received datagram must be exactly 120 bytes, without `MSG_TRUNC`, in exact frame order. After the 16th frame a bounded 50 ms timeout must observe no extra datagram. Initial messages are never skipped or resynchronized and no tolerance is invented; a receive or timing failure preserves the exact failed frame as evidence.

`state_preserved` and `state_reset` hash maps are nonempty maps of at most 1024 entries with safe relative paths (no leading slash, no `..` components) and lowercase 64-hex values. The retained-phase reset renames the guest-only `/var/lib/bluetooth` to the fixed backup `/var/lib/pb053-retained-bluetooth`, which must not already exist, then creates an empty new directory; retained state hashes are preserved rather than deleted, and key files are never exported. `original_hashes` must equal the `state_preserved` hashes taken at backup time; hashes observed after the retained phase may legitimately differ because the retained daemon may update its GATT cache, so equality across that boundary is not required and must not be faked.

The same controller identities stay fresh-1, retained, fresh-2 across the three phases. Retained mode observes loaded bonds and calls `Connect`; retained success is never satisfied by a second `Pair` call, injected bond keys or a faked `Paired` state. A daemon restart is never treated as a fresh kernel or controller reset.

Six actor labels are tracked, exactly `dbus`, `monitor`, `emulator`, `bluez-fresh1`, `bluez-retained`, `bluez-fresh2`. Each starts once with a positive integer PID (bools invalid), a nonempty argv list and a unique PID, and stops once with the same PID and exact integer return code 0, after its start. All starts and stops are counted; the validator never filters away an extra actor or failure.

Guest public execution separates capture, parse and accept: the real child exit code and marker are retained, parsed with `require_success=False`, the public stage operation is appended with the complete result and `child_exit_code`, and acceptance fails afterwards if the child exited nonzero or reported not ok, so the structured result is never lost to an early exception. A successful result contains no `failed_frame` or `unexpected_iso` event; wrong frame bytes with a recomputed self-hash still fail.

## Process ownership

`run_owned` in `scripts/bluez_host_process.py` runs one command in its own process group on the host main thread only. The timeout must be a positive, finite number and the output log path must be a new regular file in an existing parent directory. A first SIGINT or SIGTERM is latched, later signals do not overwrite the recorded first one, and original handlers are restored in all exit paths except after SIGKILL of the owner. A run is accepted only when the child exited zero with no timeout, no recorded cancellation signal, no output-limit overflow, no cleanup error and no unexpected fault. An exit-zero leader that leaves live group members cannot serve as proof of an owned stop, even if cleanup later removes them.

`DescendantScope` in `scripts/bluez_host_descendants.py` requires sole main-thread entry with no existing direct children and sets the Linux child-subreaper flag on its own process, so detached grandchildren adopted later in the same process are captured and reaped. A pidfd signal is sent only after the child's parent and `stat` start time are rechecked against the recorded (PPID, start) pair; a reused PID without both rechecked identifiers is not signalled. Cleanup is bounded to 8 seconds in total, the saved subreaper flag and original handlers are restored, and pidfds are closed. The scope never kills by name matching or targets any unknown host process; a normal body that leaks a child fails the record even if the scope's own cleanup removed it. Process-group cleanup alone is not proof against detached grandchildren.

The guest-side `stop_owned_actor` (`scripts/bluez_guest_init.py`) rejects any actor already observed to have exited, including exit code 0; a `stopped` record alone never proves liveness up to the owned stop. On TERM it waits 5 seconds, then on timeout KILLs and waits another 5 seconds; a forced kill or a nonzero terminal exit fails. These waits are bounded expectations, not an atomic liveness guarantee.

The outer pytest owner (`scripts/bluez_host_lane.py`) bounds the actual pytest run at 1500 seconds with an 8 MiB stdout cap. On the host run, the first signal is held across input snapshots, VM ownership, post-processing and record sealing. The final record publishes `cancelled_signal` and a `cancellation` boolean and never infers cancellation from a timeout; the seal rewrites at most once as a failure if a late signal arrives during publication, preserves the original error on unrelated failures, and restores handlers only after the seal.

Each run generates an independently lowercase 32-hex run ID plus the canonical guest boot UUID; the shared validator requires the host's expected run/scenario and rejects a producer-picked ID as an independent freshness anchor. Stale IDs, wrong scenarios and invalid boot UUIDs all fail. Hold runs never emit an accepted final guest ledger or claim unexecuted public cases; a cancellation or timeout fails even when QEMU itself exits zero or a forged complete marker exists.

## Evidence integrity and raw monitor

Preparation and the lane read only bounded inputs. Files are opened with `O_NOFOLLOW`, must be regular files, and are size-checked; read counts stay bounded even where a `/proc` file reports size 0 yet contains bytes. The caller-supplied digest binds the manifest and copied input bytes for trusted local execution; these checks do not authenticate artifacts against a hostile same-user process.

Nine frozen logical source keys are pinned by hash: `host`, `guest`, `public`, `results`, `monitor`, `acquire`, `limits`, `process` and `emulator`. The host runner keeps reading the host-side original sources outside the guest; the external verified `host-source.py` copy stays in preparation evidence and is never a guest program. Only the guest executes the staged guest programs, and live and copied hashes must match the frozen source map before archive and manifest creation.

Event records are finite JSON deep-copied under a lock, with the quota enforced before append and the first serialization or quota error latched. Sticky means later successful appends never clear the recorded error. `safe_append` records cleanup evidence as failure without truncation or eviction of accepted data, so the remaining resource cleanup still runs, and the final result fails whenever that happened. An ordinary append quota error cannot prevent either lease descriptor from being closed: cleanup attempts both closes after a ledger failure, and any close error remains a failed record.

The complete-marker parser (`complete_marker_lines(content, prefix, max_line_bytes=4096)`) requires byte content, a nonempty byte prefix ending with a space and a positive exact-integer cap. Only LF-terminated complete rows are consumed, optionally stripping one CR; a matching or trailing partial row over the 4096 cap is rejected, and a trailing partial marker is never returned even if its JSON appears closed. Malformed complete JSON and duplicate rows stay visible to the caller for rejection rather than being dropped or retried; there are no bad-JSON retries. The hold runner asserts at most one complete `PB053_HOLD_READY` row, decodes and checks its readiness nonce and owned QEMU identity. Evidence from a cancelled run is preserved and reported as failure, not success.

The raw monitor socket boundary is `recvmsg(65541, 256)` per packet, requiring at least 6 bytes and a header length that equals the actual payload. The header is the packed little-endian `<HHH` (opcode, index, length); the collector never decodes PAC, codec or GATT payload and keeps every opcode. A stream SHA-256 hashes each datagram prefixed with its four-byte little-endian length; counts and hash are recorded only after each emitted row and no packet-history list exists. The Linux x86-64 ancillary ABI is fixed: the timestamp ancillary is 16 bytes and the drop ancillary is 4 bytes. `reported_drops` null means drop observation was unavailable, not zero loss. Kernel timestamps are observation times, not RF or presentation timing.

Raw monitor payloads may contain ephemeral bond keys, so raw logs are retained privately as external evidence only and are never copied into Git or uploaded. The raw collector is a capture witness, not a golden payload oracle; the final payload comparison uses a separate expected-corpus audit. No host crypto or module mutation occurs, and success does not approve new SDK versions or corpora; the kernel/emulator crypto runtime stays the provided pinned profile.

An empty AF_UNIX `SOCK_SEQPACKET` read alone is not EOF or hang-up proof. Revocation requires the exact boolean true `pollhup` and actual `POLLHUP` bit, exact boolean `eof` with the `POLLIN` bit additionally when `eof` is true, and no `POLLNVAL`. A pure `POLLERR`, unread leftover data or truncated input all fail.

## Guest guards and accounting

`/init` verifies PID 1 before any mount, and the Python guest PID 1 plus the exact `pb053_guest=1` cmdline token and runtime file are checked before any dbus/GI import or bus access; every public child runs with the same guard. The archive contains a `dev/console` character entry (major 5, minor 1) created only by cpio serialization; no host `mknod` or sudo creates it.

The guest child imports dbus/GI from three exact private roots (dbus-python 1.4.0, PyGObject 3.54.5 and glib 2.86.3 typelibs), staged as store-requisite copies with explicit private `PYTHONPATH`/`GI_TYPELIB_PATH`, never a host environment export. The installed binding's `threads_init` existence is a dated reviewed fact. Environment.d link origins come only from the exact pinned systemd-minimal `GUEST_ENV_LINKS` roots, never the host `/etc/environment` target. The lane never copies or imports a GPL BlueZ functional-test implementation; GPL/LGPL runtime component notices stay retained in the private runtime.

The suite's `conftest.py` implements `pytest_collection_finish`: it enumerates the actual `session.items`, records nodeids and `(classname, name)` IDs into an exclusive suite-root `collection.json` with the pinned pytest version, never copies the reviewed policy list into the observed universe, and rejects every unexpected module or wrapper. Partial or missing JUnit, a pytest spawn failure or an interrupted or signaled pytest, and owner cleanup faults cannot pass even when the XML looks green; native JUnit is retained as original bytes. The existing nine-case inventory and four negative controls stay, negative accounting controls make new copies only and leave the original accepted report untouched. The manual nine-case VM lane remains manually selected, not automatically run in canonical CI, and establishes no physical or codec acceptance.
